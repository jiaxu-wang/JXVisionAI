# 训练操作示例：未戴眼镜检测（全流程）

本文档以 **「未戴眼镜」** 专模为例，说明从采图、标注、训练、测试到一键部署上线的完整操作。  
同类双类违规检测（安全帽、口罩等）可参照同一套路。

---

## 1. 能力说明

| 项 | 内容 |
|----|------|
| 检测键 | `no_glasses`（管理端显示：**未戴眼镜**） |
| 模型目录 | `models/specialists/no_glasses/`（`model.pt` + `specialist.json`） |
| 专模类型 | `kind = violation`（双类违规：违规类 vs 合规类） |
| 类别契约 | `0 = no_glasses`（未戴，**违规/告警**）· `1 = glasses`（已戴，合规） |
| 训练模板 | 训练实验室 → 场景模板 **「未戴眼镜」** |
| 基础模型 | `models/yolo26s.pt`（须已下载，见 getting-started） |
| 告警逻辑 | 人物框附近有「未戴」框，且无关联「已戴」框 → 持续时长达标后告警 |

> 类别顺序不可颠倒，否则会出现「戴眼镜反而告警」。

---

## 2. 前置条件

```bash
cd /home/wjx/code/python/JXVisionAI

# 确认预训练权重（YOLO26）
ls -lh models/yolo26s.pt

# 整栈（推荐）或仅依赖 + 宿主机进程
docker compose up -d --build
# 或：docker compose up -d redis && ./stop.sh 2>/dev/null; ./start.sh
```

- 管理端：Compose `http://服务器IP:15000`；宿主机 `./start.sh` 则为 `:5000`
- 登录密钥：`VISIONAI_SECRET` / `config.ini` 中 `visionai_secret`
- 至少一路可用 RTSP（事件监控中已配置，或训练页直接填 URL）

---

## 3. 新建训练项目

1. 打开 **训练实验室**
2. **新建项目**
3. 场景模板选：**未戴眼镜**（会自动填充类别 `no_glasses, glasses`）
4. 标题示例：`办公区-未戴眼镜`
5. 创建后确认训练参数（模板默认）：
   - epochs：`80`
   - batch：`8`
   - imgsz：`640`
   - device：有 GPU 填 `0`，否则 `cpu`
   - pretrained：`yolo26s.pt`（建议写成 `models/yolo26s.pt`）

---

## 4. 采图

### 4.1 RTSP 截帧

1. 「1. RTSP」选择 Redis 流或粘贴 `rtsp://...`
2. **预览一帧** → 确认画面
3. **截帧到数据集**（多角度、多光照、多人脸反复截）

### 4.2 生产快照回流（可选）

线上已有相关截图时：

1. 「2b. 生产快照回流」→ 加载快照 → 勾选 → **导入选中**
2. 导入后仍须人工标注/审核

### 4.3 数据量建议

| 阶段 | 已审核张数 | 说明 |
|------|------------|------|
| 开训硬门槛 | ≥50 | 每类框 ≥30；val/test 各 ≥10 |
| 建议上线 | ≥120～200 | 两类尽量均衡；含侧脸、远距、逆光、墨镜 |

**不要**使用自测脚本生成的 `test_xxx.jpg` 纯色假图。

---

## 5. 标注

1. 样本列表点开图片
2. 类别选 `no_glasses` 或 `glasses`
3. 在**人脸/眼镜区域**拖框（框脸部即可，勿框整身）；点选后可拖移/拖角改大小
4. **Ctrl+Z** 撤销、**Ctrl+Y** 重做；**Delete** 删选中框；**←/→**（或 **A/D**）上一张/下一张（切换前自动保存）；**S** 或「保存标注」→ 绿点 = 已审核
5. 预标注（可选）：写入**黄点草稿** → 人工改完再保存，或「全部草稿审核通过」

### 标注对照

| 画面 | 类别 |
|------|------|
| 可见镜框/镜片 | `glasses` |
| 墨镜 | 一般标 `glasses` |
| 完全无眼镜 | `no_glasses` |
| 看不清 | 宁可不标，勿乱标 |

数据检查应显示 **可开训**，并给出 train/val/test 预估（互斥划分）。

---

## 6. 训练

1. 确认数据检查通过
2. **开始训练**（未达门槛不可强制开训，除非调试环境变量）
3. 等待任务完成，查看：
   - **Val** mAP / P / R（调参参考）
   - **Test** mAP / P / R（**上线依据**）

### 默认上线门禁

- 测试集 mAP@0.5 ≥ **0.40**
- Precision ≥ **0.35**
- Recall ≥ **0.35**

未达标：补难例、平衡两类、加 epochs，或换 `yolo26m.pt` 再训。  
达标后界面显示 **「已达上线门禁，可部署」**。

---

## 7. 训练后测试（部署前）

### 7.1 实验室验证

「5. 验证模型」：

1. 选择本项目 `best.pt`
2. **单次：当前 RTSP 截一帧** 或上传静态图
3. conf 建议先 `0.25`～`0.40`
4. 可开 **RTSP 循环验证** 观察一段时间
5. 日志中看命中框与低阈值候选，排查「有框被滤掉」

### 7.2 抽检清单

- [ ] 未戴眼镜的人是否稳定检出
- [ ] 已戴眼镜是否误报为未戴
- [ ] 远距 / 侧脸 / 逆光是否可接受
- [ ] 无人脸空景是否大量误报

### 7.3 阈值向导（可选）

「6. 阈值向导」在验证集上扫 conf，得到建议阈值。  
部署时向导建议值会写入 `models/specialists/no_glasses/specialist.json`（如 `conf`、`score_threshold`、`min_duration_sec`）。  
后续调参需 **重新部署** 或手动编辑该 JSON 后刷新检测目录（**无需** 改 `config.ini`，也**没有** `glasses_*` 配置项）。

---

## 8. 一键部署

1. 训练任务显示 **已达上线门禁**
2. 点击 **一键部署到线上**
3. 按提示确认（或使用模板默认值）：
   - **key**：`no_glasses`（建议与模板一致）
   - **name_zh**：未戴眼镜
   - **kind**：`violation`
4. 系统将：
   - 复制 `best.pt` → `models/specialists/no_glasses/model.pt`（旧文件自动 `.bak_*.pt`）
   - 校验类别顺序为 `no_glasses, glasses`
   - 写入 `specialist.json`（含阈值、kind、类别契约等）
   - **不会** 写入 `config.ini` 的 `glasses_model_path`（该键已废弃）
5. 专模 **热加载**：一般 **无需重启**；刷新管理端检测类型目录即可
6. 打开 **事件监控** → 对应流 **检测类型配置** → 勾选 **未戴眼镜** → 保存

---

## 9. 上线后验收

1. 站在镜头前：**不戴眼镜**应在持续约 1s 后产生告警与截图  
2. **戴上眼镜**后告警应停止（或不再新增）  
3. 历史告警中类型为「未戴眼镜」  
4. 误报/漏报截图用「快照回流」补进同一项目 → 再训 → 再部署（迭代）

## 11. 常见问题

| 现象 | 处理 |
|------|------|
| 检测类型里没有「未戴眼镜」 | 确认已部署专模；刷新管理端 / 检测目录（通常无需重启） |
| 一键部署按钮灰/没有 | Test 未过门禁；看任务区门禁错误 |
| 戴眼镜也告警 | 检查类别是否标反；须 `0=no_glasses, 1=glasses` |
| 训练卡住下载权重 | 确认 `models/yolo26s.pt` 存在，pretrained 填 `models/yolo26s.pt` |
| 自定义模板也能部署 | 「自定义」同样可部署为专模（填写 key/name/kind）；眼镜场景仍推荐模板 **「未戴眼镜」** 以自动填充类别与 kind |
