# 国标 GB/T 28181

平台作为**上级 SIP 平台**，摄像机作为下级设备注册。信令由独立进程 `visionai-sip` 处理；媒体由摄像机把 PS/RTP 推到 **ZLMediaKit**，worker 再从 ZLM 拉 `rtsp://…/rtp/{设备}_{通道}` 做分析。

> 预览 ≠ 分析。接入平台后设备可以在线、可以预览；只有通道点了 **接入分析** 才会写入检测配置并由 worker 拉流。

更短的操作步骤见 [user-guide.md](user-guide.md#国标-28181)。

---

## 配置三组（互不回退）

| 组 | 页面位置 | Redis | 用途 |
|----|----------|-------|------|
| **SIP 信令** | 设备接入 → 国标 28181 | `{prefix}gb28181/platform` | 平台 ID/域、监听、对外地址、传输协议、密码策略 |
| **媒体收流** | 同上「媒体收流（Invite / ZLM）」 | 同一 platform 文档的 `media_ip` / 端口范围 | Invite SDP 里摄像机推流的目的 IP/端口，**不要填成 SIP 对外地址凑合** |
| **设备账号与通道** | 设备列表 + **通道**弹窗 | `{prefix}gb28181/devices` | SIP 用户、认证 ID、密码、通道编码与别名 |

默认 SIP 监听 **15060**（TCP）。Compose 映射 `15060/tcp`+`15060/udp`；ZLM 收流映射 **10000–10200** 的 TCP 与 UDP。改 SIP 监听后必须重启 `visionai-sip`（Compose：`docker compose restart visionai-sip`；宿主机：`./stop.sh && ./start.sh`）。

## 接入 vs 分析

| | 接入平台 | 接入分析 |
|--|----------|----------|
| 做什么 | SIP 注册成功，列表显示**在线** | 对该**通道** Invite 收流，写入 `streamlist`（`analyze: true`） |
| 在哪操作 | 设备列表看 SIP 状态；通道在「通道」里维护 | **通道配置**里点「接入分析」 |
| 之后 | 可预览（点播，关预览可 BYE） | 出现在「检测配置」，勾选检测类型后 worker 自动保活 Invite |

- 设备列表**状态列只表示 SIP 用户在线/离线**，不显示「已接入分析」。
- **预览 / 接入分析 / 检测配置**都在通道弹窗，按通道操作（Invite 的 To 是通道编码）。
- 通道别名修改后会同步到已接入分析的流名称（检测配置显示该名称；分析线程按流 `id` 识别，改名不会拆成两路）。

检测配置里点删除：

- **RTSP / ONVIF**：`PATCH analyze=false`，设备仍留在接入列表，可再点「接入AI分析」。
- **国标**：删除该路 stream（并发 BYE），SIP 账号与通道保留，可再「接入分析」。

## 摄像机侧填写

设备行点 **复制**，把清单贴到摄像机「上级平台 / 国标」页。常见对应关系：

| 摄像机项 | 填什么 |
|----------|--------|
| SIP 服务器 ID / 域 | 平台 `server_id` / `domain`（默认 `34020000002000000001` / `3402000000`） |
| SIP 服务器地址 / 端口 | 平台**对外** IP 与端口（默认 **15060**，不是摄像机本机 5060） |
| 传输协议 | 与平台一致，推荐 **TCP** |
| SIP 用户名 / 认证 ID | 平台自动分配的 20 位编码（二者通常相同） |
| 密码 | 该 SIP 账号密码 |
| 通道编码 | 20 位，第 11–13 位类型码须为 **131/132**（视频）；**137** 为语音输出，不要当视频通道 |

海康注意：

- 设备本机 SIP 端口保持默认 **5060**（那是摄像机自己监听，不是平台端口）。
- 该型号常拒绝 `UDP/RTP/AVP`（SIP **415**）。平台 Invite 使用 **TCP/RTP/AVP** + `a=setup:passive`，媒体推到平台 SDP 里的端口。
- Invite 的 To 是**通道 ID**，不要改成 `通道@媒体IP:端口`。

WSL2 / Docker 桥接时，摄像机必须能访问宿主机（或 host/mirrored 网络）上的 SIP 与媒体 IP，不要填容器内网地址。

## 点播与收流

1. 通道点 **预览** 或 **接入分析** → API 向 `visionai-sip` 投递 Invite 命令。
2. SIP 在 ZLM `openRtpServer`：独立端口（**跳过 10000**，避免打到 `rtp_proxy` 后流名变成 SSRC 十六进制）、`stream_id={设备}_{通道}`、`tcp_mode=1`（被动 TCP）。
3. 摄像机把 PS 推到该端口；成功条件是 ZLM 直播名等于 `{设备}_{通道}`。
4. 预览走 ZLM WebRTC；分析由 worker 拉 `rtsp://{ZLM_PULL_HOST}:{port}/rtp/{设备}_{通道}`。
5. 已接入分析且检测开启时，worker 会周期性检查码率，没有流则重新 Invite。

仅预览、未接入分析时，关闭预览窗口会发 BYE（已接入分析的通道不 BYE，避免打断检测）。

## 云台 PTZ

国标云台不是 ONVIF ContinuousMove，而是向**通道**发 SIP `MESSAGE`，MANSCDP `DeviceControl`，`<PTZCmd>` 为 8 字节指令的十六进制。`DeviceID` 与 SIP To 都是通道编码。

1. 通道 **预览** 打开后，画面右侧出现云台面板（仅国标预览；RTSP/ONVIF 不显示）。标题栏可 **截图保存**。
2. 按住方向键 / 变倍连续发令，松开发 **stop**。键盘方向键、`+`/`-` 变倍同样有效。
3. 聚焦近/远、光圈±。本平台不支持预置位、巡航、扫描、辅助开关。
4. 关闭预览会再发一次 stop，避免球机继续转。

多数海康球机要求**先点播再控云台**。摄像机回 SIP 200 只表示信令收到。Catalog 的 `PTZType` 会写入通道（1 球机 / 2 半球 / 4 遥控枪机），仅作提示，未知时仍显示面板。

指令码字节（与海康一致）：bit0 右、bit1 左、bit2 上、bit3 下、bit4 放大、bit5 缩小。变倍请用面板「变倍±」，不要把左右键当变倍。

## 喊话广播

国标喊话不是 ONVIF Backchannel，流程对齐 VIDEO `gb28181gw`：

1. 通道 **预览** 后点标题栏 **麦克风**，浏览器把麦克风推到 ZLM `broadcast/{设备}_{视频通道}_{时间戳}`。
2. 平台发 SIP `MESSAGE`（`CmdType=Broadcast`）。`TargetID` 先试**当前视频通道**，再设备编码，最后才是 Catalog 里的 **137**。海康 IPC 对不存在的推导 137 会回 `ERROR` 且不再 INVITE。
3. 摄像机回 OK 后再 **INVITE** 平台；平台 200 OK（音频 `sendonly`，优先 PCMA/8000）并用 ZLM `startSendRtp` / `startSendRtpPassive` 把声送到喇叭。
4. 再点麦克风或关闭预览：SIP **BYE** + `stopSendRtp`，停止推流。

Catalog 若上报 137，会记住为语音输出通道，但不进入视频通道列表。

## 在线但点播报未注册

列表「在线」来自 Redis `{prefix}gb28181/runtime`（以及设备文档上的同步字段）。**Invite 必须信令进程内存里还有 TCP 会话**。

`./stop.sh && ./start.sh`（或只重启 sip）后内存会话为空。若仍显示在线，属于旧缓存。当前行为：

- sip 启动时把 runtime 全部置为离线。
- 心跳超时或 SIP 进程不在，列表不再显示在线。
- 摄像机 Keepalive 到达时**重建会话**（不必等下一次 REGISTER）。
- TCP 断开则清掉对应会话。

处理：重启后等一次心跳或重新 REGISTER，状态变为真正在线后再预览 / 接入分析。

## Redis 键

| 键 | 说明 |
|----|------|
| `{prefix}gb28181/platform` | SIP + 媒体平台参数 |
| `{prefix}gb28181/devices` | SIP 账号与通道 |
| `{prefix}gb28181/runtime` | 信令写入的在线/心跳（启动时会清） |
| `{prefix}gb28181/sip_alive` | sip 进程心跳（短 TTL） |
| `{prefix}gb28181/cmd` / `cmd_result:*` | API → sip 的 Invite/BYE/Catalog |

流配置仍在 `{prefix}streamlist`，国标流带 `access_method=gb28181` 与 `gb28181.{device_id,channel_id,zlm_stream}`。

## 排障

| 现象 | 处理 |
|------|------|
| 信令进程未运行 | Compose：`docker compose ps visionai-sip`；宿主机看 `logs/sip.log`，确认 `./start.sh` 起了 sip |
| 一直离线 | 摄像机 SIP 服务器 IP/端口/协议是否指向本平台；账号是否已保存；平台是否勾选启用 |
| 在线但「设备未在 SIP 注册」 | 见上一节；等心跳或重启摄像机国标 |
| Invite 415 | 海康拒绝 UDP RTP；确认走 TCP 收流，不要按其它网关的 UDP SDP 去改 |
| 有 Invite 无画面 | 媒体 IP 必须是摄像机可达地址；端口范围 10000–10200 已映射 TCP+UDP；ZLM 日志看是否推到 `rtp/{设备}_{通道}` |
| 流名是 8 位十六进制 | 打到了 ZLM `rtp_proxy:10000`；平台会跳过 10000 并指定 stream_id |
| 通道里预览被挡住 | 刷新页面（预览弹窗 z-index 高于通道配置） |
| 云台无动作 | 先打开该通道预览；确认 SIP 已注册；松开方向键应停止。200 不代表云台真动 |
| 喊话无声 | sip 日志若 `Broadcast result=ERROR` 且无 INVITE：摄像机没有该 TargetID。现已先用视频通道再回退设备编码。需重启 sip 后再试 |
| 第一次有声、关麦再开无声 | 设备 INVITE 早于 ZLM 把 WebRTC 转成 rtsp。现已等 rtc 源就绪再 Broadcast，INVITE 时重试 `startSendRtp`。重启 sip、硬刷新页面后再试 |
| 开麦后约 2 秒才有声 | 不要等 rtsp 转封装再 Notify。页面硬刷新后开麦应几乎立刻能喊 |

HTTP 接口见 [api.md](api.md#国标-gbt-28181)。
